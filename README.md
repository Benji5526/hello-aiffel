# 컴퓨팅 사고법으로 업무 자동화하기: CS 응대 & SNS 포스팅

## 도메인 맥락
- **도메인**: 마케팅 (1년 차)
- **자동화/정리 대상 업무**: 반복되는 커스터머 서비스(CS) 응대, SNS 포스팅 업로드

마케팅 실무에서 매일 발생하는 CS 문의 응대와 정기적인 SNS 콘텐츠 발행은 반복성이 높지만 수작업으로 처리되는 비중이 커서, 컴퓨팅 사고법(분해·패턴 인식·추상화·알고리즘)을 적용해 자동화/구조화할 대상으로 선정했다.

## 컴퓨팅 사고법 적용

### 1. 분해 (Decomposition)
전체 업무를 독립적으로 처리 가능한 단위로 쪼갠다.

- **CS 응대**
  - 문의 접수 (채널 확인: 카카오톡, 이메일, 댓글 등)
  - 문의 유형 분류 (배송 / 가격 / 제품 스펙 / 기타)
  - 유형별 답변 작성
  - 답변 발송 및 기록
- **SNS 포스팅**
  - 콘텐츠 소재 확보 (이미지, 카피 문구)
  - 채널별 포맷 변환 (인스타그램, 페이스북 등 사이즈/텍스트 길이 상이)
  - 업로드 일정 배정
  - 예약 발행 및 게시 확인

### 2. 패턴 인식 (Pattern Recognition)
반복되는 규칙성을 찾는다.

- CS 문의의 80% 이상이 배송/가격/스펙 3가지 유형에 집중되며, 유형별로 사용되는 문구가 거의 고정되어 있다.
- SNS 포스팅은 요일·시간대별로 발행 주기가 정해져 있고(예: 매주 화·목 오후 2시), 채널별 포맷 규칙(이미지 비율, 해시태그 개수)이 고정적이다.
- 두 업무 모두 "정형화된 대다수 케이스"와 "사람이 판단해야 하는 예외 케이스"로 나뉜다는 공통 패턴이 있다.

### 3. 추상화 (Abstraction)
핵심만 남기고 불필요한 세부사항을 제거해 단순한 모델로 만든다.

- CS 응대: 유형별 **답변 템플릿 3종**(배송/가격/스펙)으로 단순화하고, 각 템플릿의 변수(주문번호, 상품명 등)만 채워 넣는 구조로 추상화한다.
- SNS 포스팅: 콘텐츠를 **시트(스프레드시트) 한 행 = 게시글 한 건**으로 추상화하여, `업로드일시 / 채널 / 이미지 URL / 본문 텍스트 / 해시태그` 열만 관리하면 되도록 데이터 구조를 단순화한다.

### 4. 알고리즘 (Algorithm)
자동화 로직을 순서도 형태로 정의한다.

```
[CS 응대]
문의 유입
  → 키워드 기반 유형 자동 분류 (배송/가격/스펙/기타)
    → 정형 유형이면: 템플릿 매칭 → 변수 채워 1차 답변 초안 생성 → 담당자 확인 후 발송
    → '기타'로 분류되면: 자동 처리 없이 즉시 담당자에게 알림

[SNS 포스팅]
예약 시각 도래
  → 시트에서 해당 게시물 데이터 조회
    → 데이터 정상(이미지/본문 존재): 채널별 포맷 변환 → 예약 발행 실행
    → 데이터 누락/이상: 발행 보류 + 담당자에게 알림
```

## 출력 요구
- 형식: 마크다운(Markdown) 문서
- 언어: 한국어

## 검증 기준
마케팅 팀장이 다음을 확인했을 때 이 자동화가 성공했다고 평가한다.
- CS 응대 소요 시간이 기존 대비 **50% 이상 단축**되었을 것
- SNS 포스팅이 **누락 없이 정상적으로 예약 발행**되었을 것
